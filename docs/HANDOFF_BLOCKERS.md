## 5. Что нельзя сделать программно

Все три пункта проверены запросами к API. Ни один нельзя выполнить из кода.

### 5.1. Перевод приложения в Live

API для переключения режима приложения у Meta не существует ни в Graph API,
ни в Marketing API. Только тумблер в панели приложения.

### 5.2. Заполнение URL политики конфиденциальности

Поле `privacy_policy_url` у приложения пустое, а Meta требует его перед
переводом в Live. Запись через API заблокирована:

```text
(#10) Changing app settings through API calls has been disabled for this app.
Go to your app's advanced settings to enable this.
```

Включение этой возможности само по себе выполняется вручную в расширенных
настройках приложения.

### 5.3. Лимит расходов рекламного аккаунта

Ранее у аккаунта был `spend_cap = 1` (0,01 PLN). System User не мог менять
лимит (`1487828`). К 29.07 лимит поднят (~2850 PLN), доставка идёт.
### 5.4. Обходной путь через другое приложение

Ограничение действует на конкретное приложение. Если бы у бизнеса
`Artox Media RB` было другое приложение в режиме Live, можно было бы выпустить
токен через него и разместить объявления без ожидания. Доступных приложений в
бизнесе не обнаружено: `owned_apps` и `client_apps` возвращают пустой список.

## 6. Что должен сделать человек с доступом

Выполняется один раз, занимает несколько минут.

1. Открыть <https://developers.facebook.com/apps/1045577707887803/>.
2. Перейти в «Настройки» → «Базовые».
3. Заполнить «URL политики конфиденциальности» ссылкой на страницу политики
   конфиденциальности сайта `kravira.by`.
4. При необходимости заполнить остальные обязательные поля, которые Meta
   подсветит: значок приложения и категория.
5. Сохранить изменения.
6. Вверху панели приложения переключить режим с «В разработке» на
   «Действующий».
7. В Ads Manager или Business Manager открыть настройки платежей рекламного
   аккаунта `act_723170300839405` и снять либо поднять лимит расходов,
   который сейчас равен 0,01 PLN.

Готовый текст запроса агентству находится в разделе 8.

## 7. Как продолжить работу с другого компьютера

```bash
git clone https://github.com/akuazuk/meta.git
cd meta
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Скопировать `.env` с рабочей машины или заполнить по `.env.template`, затем:

```bash
chmod 600 .env
```

Проверить, сняты ли блокеры:

```bash
python -m scripts.diagnose_blockers
```

Скрипт только читает данные и использует `validate_only`, ничего не создаёт и
не изменяет. Он покажет по каждому блокеру статус `ok` или `blocked`.

Когда все проверки станут `ok`, завершить размещение:

```bash
python -m scripts.create_test_campaign --check
python -m scripts.create_test_campaign --create
python -m scripts.create_test_campaign --verify
```

Всё создаётся в статусе `PAUSED`. Перевод в `ACTIVE` выполняется отдельно и
только после подтверждения владельца.
